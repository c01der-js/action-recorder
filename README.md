# Action Recorder — Windows + 1С (и macOS)

Записывает, что делает сотрудник, и превращает запись в:
- **instructions.md** — сценарии для ИИ-агента (computer use), по одному на каждую повторяемую задачу;
- **summary.md** — резюме о работе: что сделано, время по программам и задачам, рутина, ошибки, что автоматизировать.

## Что записывается

| Данные | Подробности |
|---|---|
| Клики, перетаскивания, прокрутка | координаты, кратность клика, скриншот с отметкой места клика |
| Элемент под курсором (Windows) | название кнопки или поля и родительской формы через UI Automation, например «Провести и закрыть» в «Поступление (акт, накладная)» |
| Ввод текста | склеивается в строки, Backspace учитывается, кириллица по раскладке активного окна |
| Горячие и служебные клавиши | Ctrl+Enter, F4, F8, F9, Ins, Enter, Tab; повторы стрелок склеиваются («down ×5») |
| Буфер обмена | что скопировано или вставлено (Ctrl+C/X/V, Ctrl/Shift+Ins), до 300 символов |
| Активное окно | процесс и заголовок; окна 1С (тонкий и толстый клиент, веб-клиент) помечаются отдельно |
| Траектория мыши | moves.jsonl, раз в 0.2 c |

## Где запускать: 1С на терминальном сервере

Если операторы заходят на сервер по удалённому рабочему столу (RDP) и 1С работает там, рекордер ставится **на сервер** и работает **внутри RDP-сессии каждого оператора**.

Почему не на компьютере оператора: локально видно только окно «Подключение к удалённому рабочему столу». Нет ни окон 1С, ни названий кнопок, а нажатия клавиш RDP-клиент часто перехватывает раньше рекордера. Локальная запись допустима только как запасной вариант, если на сервер ставить нельзя: останутся клики и скриншоты, клавиатура частично.

**Развёртывание на сервере (делает администратор):**
1. Скопировать проект в `C:\ActionRecorder`. Поставить Python и зависимости (раздел ниже) или собрать `recorder.exe`.
2. Создать папку записей, например `D:\Recordings`. Операторам дать право только на запись в неё, руководителю — на чтение.
3. В `start_recorder.bat` поправить пути и при необходимости список логинов (`RECORD_USERS`).
4. Положить ярлык на `start_recorder.bat` в `C:\ProgramData\Microsoft\Windows\Start Menu\Programs\StartUp`. Тогда рекордер стартует при каждом входе оператора на сервер.

**Как это работает:**
- Каждый оператор пишется в свою папку `D:\Recordings\<логин>\<дата_время>`.
- В одном сеансе не запустится второй экземпляр.
- В полночь начинается новая папка.
- Раз в минуту всё сбрасывается на диск: если оператор вышел из сеанса, запись не теряется.
- Пока RDP-сеанс отключён, ничего не пишется. После переподключения запись продолжается.
- Нагрузка: скриншот только в момент действия, около 100–200 КБ. Перед раскаткой на всех проверьте на 2–3 операторах.

## Установка (Windows)

1. Python 3.11+ с python.org (при установке отметить «Add to PATH»).
2. В папке проекта:
   ```bat
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   set ANTHROPIC_API_KEY=sk-ant-...
   ```

Если 1С запущена **от имени администратора**, рекордер тоже нужно запускать от администратора. Иначе Windows не даст видеть ввод в это окно.

## Использование

```bat
python recorder.py                     :: запись; Ctrl+Shift+F11 — пауза, Ctrl+Shift+F12 — стоп
python recorder.py --max-minutes 480   :: остановится сама через 8 часов
python generate.py sessions\<папка> --dry-run   :: журнал и объём без вызова API
python generate.py sessions\<папка>             :: сценарии + резюме
```

Опции рекордера: `--no-text` (текст и буфер обмена не сохраняются, только длина), `--no-screens`, `--no-clipboard`, `--no-elements`.
Опции генератора: `--model`, `--max-images` (по умолчанию 30 на запрос или фрагмент), `--workers`.

Запись до 30 минут обрабатывается одним запросом. Более длинная, например рабочий день, режется на фрагменты по 20 минут: по каждому делаются заметки (`notes/`), из них итоговые сценарии и резюме.

## Готовый recorder.exe (без Python на сервере)

`.exe` собирается автоматически на GitHub при каждом изменении в ветке `main`.

**Где скачать:**
- вкладка **Actions** → последний зелёный запуск «Build recorder.exe» → внизу артефакт **ActionRecorder**;
- или вкладка **Releases**, если поставлен тег `v…` (например `git tag v1.0 && git push --tags`), → `ActionRecorder.zip`.

**Что внутри архива:**

| Файл | Назначение |
|---|---|
| `recorder.exe` | рабочая версия: без окна, работает в фоне |
| `recorder-console.exe` | та же программа с окном: для проверки и отладки |
| `start_recorder.bat` | автозапуск при входе оператора |
| `selftest.json` | результат проверки сборки на GitHub |

**Установка на сервер:**
1. Распаковать архив в `C:\ActionRecorder`.
2. Проверить работу внутри RDP-сеанса: `C:\ActionRecorder\recorder-console.exe --selftest`. Во всех строках должно стоять `ok`.
3. Дальше по разделу «Развёртывание на сервере».

`recorder.exe` останавливается только по Ctrl+Shift+F12 или при выходе из сеанса. Антивирус может ругаться на перехват клавиатуры: добавьте папку в исключения.

**Ручная сборка на любой Windows:**
```bat
pip install -r requirements.txt pyinstaller
pyinstaller --onefile --noconsole --collect-all uiautomation --name recorder recorder.py
```

## Ограничения

- **UI Automation в 1С.** Насколько полно тонкий клиент отдаёт названия элементов, зависит от версии платформы. Если названий нет, смысл действий берётся со скриншотов.
- **Объём одного фрагмента.** До 30 скриншотов на 20 минут. Для точных пошаговых сценариев внутри 1С надёжнее штатная запись действий 1С + Vanessa Automation.
- **Исполнение агентом в 1С.** Клики по интерфейсу 1С ненадёжны. Для боевого исполнения лучше API 1С (OData, HTTP-сервисы) или обработки.

## Приватность и закон

- Скриншоты и тексты уходят в API Anthropic. Для чувствительных данных используйте `--no-text`, паузу и ограничение по времени.
- Сотрудник должен быть письменно уведомлён о мониторинге: локальный акт или пункт в трудовом договоре.
- Запись кейлоггера и скриншотов — это персональные данные, нужна правовая основа для их обработки.
